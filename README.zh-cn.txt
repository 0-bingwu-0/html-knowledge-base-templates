# html-knowledge-base-templates

用于知识库的 HTML 模板，以及用于填充这些模板的技能（skills）。

> **需要一个应用来查看和组织输出结果？** 生成的文件是自包含的 HTML，可在任何浏览器中打开。但如果您想要一个专门的知识库应用，请尝试 [stashbase](https://github.com/liliu-z/stashbase)。

## 为什么笔记要用 HTML

HTML 过去之所以没能普及，是因为必须由人类来编写。

一个自包含的 HTML 文件可以提供丰富的布局、混合媒体和交互性——而且其格式在产生它的工具消失很久之后依然有效。

很少有格式能同时具备这些特点。

我们之前妥协，是因为人类不愿意为每一篇阅读笔记、会议回顾和论文摘要手动编写 HTML。Markdown 之所以在笔记格式大战中获胜，并非因为它更具表现力——事实上它远逊于 HTML——而是因为它是人类输入时摩擦力最低的文本格式。Obsidian、Notion 和 Bear 默认使用 Markdown 或类似 Markdown 的格式也是出于同样的原因。

而这个限制现在消失了。模型编写 HTML 并不比编写 Markdown 更慢或更难——对于 LLM 来说，两者都只是文本。如果我们不再需要手动输入文件，就没有理由继续承受 Markdown 的限制：没有真正的排版、没有图文混排布局、没有可展开的部分，也没有可控的布局。

Markdown 不会消失。对于快速草稿、日志和需要手动编辑的文件，它仍然是正确的格式，两者将在很长一段时间内共存。但对于笔记的*最终完成、可分享、可归档*版本，HTML 才是你想要的——而产生它的成本现在已经骤降。

## 缺失的一环

现在的障碍不再是生成。模型已经可以做到这一点。障碍在于模板。

网络上充斥着用于落地页（landing pages）、管理后台、作品集网站和营销套件的 HTML。**而用于知识库的 HTML 模板几乎不存在。** 那些专为长篇阅读内容设计、注重排版、内容优先、无依赖、相当于排版精美的书籍章节的即插即用模板，出奇地难以找到。

本仓库就是这些模板的集合。每个套件（kit）包含一个模板及其填充该模板的技能。投入原始内容，运行斜杠命令，即可获得一个完成的 HTML 页面。

## 包含内容

每个顶层文件夹都是一个自包含的**套件（kit）**——包含一个模板 + 相应技能 + 一个示例：

- [`podcast-question-cards/`](podcast-question-cards/) — 长篇访谈转录 $\rightarrow$ 带有可展开原文段落的 Q&A 知识卡片
- [`lecture-case-cards/`](lecture-case-cards/) — 课程讲座转录 $\rightarrow$ 公司案例研究卡片（示例语料：Stanford CS183B）

（更多套件即将推出）
